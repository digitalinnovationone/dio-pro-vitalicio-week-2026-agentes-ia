Conceitos

Os 12 fundamentos do Claude Code

Cada card traz o conceito, uma descrição que cabe em uma live, uma dica prática e um link para o glossário oficial, que aprofunda o termo e conecta com a documentação completa.

  • 1

    CLAUDE.md

    Arquivo de memória do projeto que o Claude lê no início de toda sessão. Concentra arquitetura, convenções e tudo que o agente precisa saber para se comportar como alguém do time.

    Dica: rode /init dentro do projeto e deixe o próprio Claude criar a primeira versão.

    Ver no glossário
  • 2

    Permissions

    Controle do que cada agente pode fazer no seu ambiente. Você libera ou bloqueia ferramentas específicas e mantém ações sensíveis sob revisão humana antes de executar.

    Dica: use Shift+Tab para alternar entre os modos default, auto-accept e plan.

    Ver no glossário
  • 3

    Plan Mode

    Modo em que o Claude monta um plano detalhado antes de mexer em qualquer arquivo. Você revisa, ajusta ou rejeita o plano e só então a execução começa.

    Dica: use sempre que a tarefa envolver múltiplos arquivos ou comandos sensíveis.

    Ver no glossário
  • 4

    Checkpoints

    Salvamento automático do estado do código antes de cada mudança. Se o agente fizer besteira ou você quiser experimentar uma abordagem diferente, dá para voltar no tempo em segundos.

    Dica: aperte Esc duas vezes ou rode /rewind para voltar a um estado anterior.

    Ver no glossário
  • 5

    Skills

    Pacotes de instrução que o Claude carrega automaticamente quando o contexto bate. Diferente do CLAUDE.md, só ocupam espaço quando são realmente usados.

    Dica: guarde em .claude/skills/ para padronizar tarefas repetitivas do time.

    Ver no glossário
  • 6

    Hooks

    Scripts que disparam automaticamente em momentos específicos da sessão, como antes de uma ferramenta rodar ou depois de uma edição. Servem para impor regras que o modelo não pode esquecer.

    Dica: use PreToolUse para bloquear comandos perigosos antes de eles executarem.

    Ver no glossário
  • 7

    MCP (Model Context Protocol)

    Protocolo aberto que conecta o Claude a ferramentas externas, APIs e bancos de dados. É o que permite o agente ler do Jira, do Postgres, do GitHub e por aí vai.

    Dica: comece integrando uma ferramenta que você já usa todo dia.

    Ver no glossário
  • 8

    Plugins

    Extensões prontas que combinam Skills, Subagents, comandos e Hooks num pacote único. Permitem adicionar novas capacidades ao Claude sem precisar escrever cada peça do zero.

    Dica: use plugins de terceiros para integrações comuns antes de criar Skills próprias.

    Ver no glossário
  • 9

    Context

    Tudo o que o Claude está enxergando agora, ou seja, arquivos carregados, histórico da conversa, regras ativas. Gerenciar isso é o que separa uma sessão lenta de uma sessão produtiva.

    Dica: rode /context para inspecionar e tire da janela o que não é mais útil.

    Ver no glossário
  • 10

    Commands

    Atalhos que disparam fluxos com um único comando, como /review ou /test. Os nativos já cobrem muita coisa e você pode criar quantos quiser.

    Dica: salve seus templates recorrentes em .claude/commands/ e versione com o projeto.

    Ver no glossário
  • 11

    Compaction

    Compressão inteligente da conversa para liberar tokens sem perder o essencial. Pode ser disparada manualmente ou acontecer sozinha quando o contexto enche.

    Dica: rode /compact antes de começar uma nova fase em sessões longas.

    Ver no glossário
  • 12

    Subagents

    Agentes especialistas que o Claude principal pode chamar. Cada um tem contexto próprio, prompt próprio e ferramentas próprias, e pode rodar em paralelo no mesmo projeto.

    Dica: defina papéis em .claude/agents/ e use /agents para gerenciar.

    Ver no glossário
